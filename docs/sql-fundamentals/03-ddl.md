# 1.7 DDL: tables and data types

!!! abstract "Chapter card"
    **Stage:** 1 · **Prerequisites:** 1.3, 1.5 · **Time:** 2 hours · **Applies to:** 19c+ (23ai additions marked)

## 1. Overview

**Data Definition Language** creates and changes the *structure* of the
database: tables, columns, indexes, views. The main verbs are `CREATE`, `ALTER`,
`DROP`, `TRUNCATE`, `RENAME` and `COMMENT`.

!!! warning "DDL commits"
    In Oracle every DDL statement issues an implicit `COMMIT` before and after
    it runs. You cannot roll back a `DROP TABLE` or `TRUNCATE`, and any pending
    `INSERT`/`UPDATE` in your session is committed when you run DDL.

## 2. CREATE TABLE

```sql
CREATE TABLE delivery_slots (
    slot_id      NUMBER(10)   GENERATED BY DEFAULT ON NULL AS IDENTITY,
    warehouse_id NUMBER(10)   NOT NULL,
    slot_start   TIMESTAMP    NOT NULL,
    capacity     NUMBER(4)    DEFAULT 20 NOT NULL,
    is_open      CHAR(1)      DEFAULT 'Y' NOT NULL,
    CONSTRAINT pk_delivery_slots PRIMARY KEY (slot_id),
    CONSTRAINT fk_slots_warehouse FOREIGN KEY (warehouse_id)
        REFERENCES warehouses (warehouse_id),
    CONSTRAINT ck_slots_capacity CHECK (capacity > 0),
    CONSTRAINT ck_slots_open CHECK (is_open IN ('Y', 'N'))
);
```

### Core data types

| Type | Holds | Notes |
|---|---|---|
| `NUMBER(p, s)` | Exact decimal, `p` digits total, `s` after the point | `NUMBER(10,2)` up to 99,999,999.99. Plain `NUMBER` is unconstrained. |
| `VARCHAR2(n [BYTE\|CHAR])` | Variable text up to `n` | Max 4000 bytes, or 32767 with `MAX_STRING_SIZE = EXTENDED`. Prefer `CHAR` semantics for multilingual data. |
| `CHAR(n)` | Fixed-length, space padded | Only for true fixed codes |
| `DATE` | Date and time to the second | |
| `TIMESTAMP [(f)] [WITH [LOCAL] TIME ZONE]` | Fractional seconds, optional zone | |
| `CLOB`, `BLOB` | Large text / binary | Stored as SecureFiles LOBs |
| `RAW(n)` | Small binary | `RAW(16)` for a GUID |
| `BOOLEAN` | `TRUE` / `FALSE` / null | :material-tag: **23ai+** as a column type |
| `JSON` | Binary JSON (OSON) | :material-tag: **21c+** |
| `VECTOR` | Embedding vector | :material-tag: **23ai+**, chapter [4.7](../oracle-26ai/01-oracle-26ai.md) |
| `BINARY_FLOAT`, `BINARY_DOUBLE` | IEEE floating point | Science, not money |

### Generated keys

=== "Identity column (12.1+)"

    ```sql
    order_id NUMBER(12) GENERATED ALWAYS AS IDENTITY
    ```

    | Variant | Behavior |
    |---|---|
    | `GENERATED ALWAYS` | You may never supply a value |
    | `GENERATED BY DEFAULT` | Used when you do not supply one |
    | `GENERATED BY DEFAULT ON NULL` | Also used when you supply `NULL` |

=== "Sequence (any release)"

    ```sql
    CREATE SEQUENCE order_seq START WITH 1009 INCREMENT BY 1 CACHE 100;

    INSERT INTO orders (order_id, ...) VALUES (order_seq.NEXTVAL, ...);
    ```

An identity column is a sequence that Oracle creates and manages for you. Both
can leave **gaps** (rollbacks, cache loss on restart). Generated keys are
unique, not gap-free; never promise the business gap-free numbers from a sequence.

### Defaults and virtual columns

```sql
created_at TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
line_total NUMBER(12,2) GENERATED ALWAYS AS (quantity * unit_price) VIRTUAL
```

A **virtual column** is computed when read and takes no storage. It can be
indexed and constrained.

### Create a table from a query (CTAS)

```sql
CREATE TABLE orders_2025_03 AS
SELECT * FROM orders
WHERE  order_date >= DATE '2025-03-01' AND order_date < DATE '2025-04-01';
```

CTAS copies data and `NOT NULL` constraints only. Primary keys, foreign keys,
indexes, defaults and triggers are **not** copied.

## 3. ALTER TABLE

```sql
ALTER TABLE delivery_slots ADD (notes VARCHAR2(200));
ALTER TABLE delivery_slots MODIFY (notes VARCHAR2(500));
ALTER TABLE delivery_slots RENAME COLUMN notes TO slot_notes;
ALTER TABLE delivery_slots ADD CONSTRAINT uq_slots UNIQUE (warehouse_id, slot_start);
ALTER TABLE delivery_slots DROP COLUMN slot_notes;
ALTER TABLE delivery_slots RENAME TO wh_delivery_slots;
```

| Change | Cost on a large table |
|---|---|
| Add a nullable column | Instant (dictionary only) |
| Add a column with a `DEFAULT` | Instant since 12c for `NOT NULL`, and for nullable columns too: the default is kept in the dictionary |
| Widen a `VARCHAR2` | Instant |
| Narrow a column, change type | Needs validation of every row, or is refused if data does not fit |
| `DROP COLUMN` | Rewrites every row. Prefer `SET UNUSED` now and drop in a maintenance window |
| Add a constraint | Validates all rows unless added `NOVALIDATE` |

Most DDL needs an exclusive lock on the table for a moment. If a session has an
uncommitted change on it, the DDL fails with `ORA-00054: resource busy`. Set
`ALTER SESSION SET ddl_lock_timeout = 30;` to wait instead.

## 4. DROP, TRUNCATE, DELETE

| | `DELETE` | `TRUNCATE` | `DROP` |
|---|---|---|---|
| Type | DML | DDL | DDL |
| Removes | Chosen rows | All rows | Rows and the table |
| `WHERE` clause | Yes | No | No |
| Rollback | Yes | No | No (but see recycle bin) |
| Triggers fire | Yes | No | No |
| Space released | No (high-water mark stays) | Yes | Yes |
| Speed on big tables | Slow (logs every row) | Fast | Fast |

!!! danger "Destructive commands"
    ```sql
    TRUNCATE TABLE wh_delivery_slots;        -- all rows gone, no rollback
    DROP TABLE wh_delivery_slots;            -- goes to the recycle bin
    DROP TABLE wh_delivery_slots PURGE;      -- gone for good
    ```
    A plain `DROP TABLE` can be undone with `FLASHBACK TABLE ... TO BEFORE DROP`
    while the object is still in the recycle bin
    ([3.4](../backup-recovery/01-backup-recovery.md)). `PURGE` and `TRUNCATE`
    cannot be undone without a backup. In production these need a change ticket
    and a verified backup.

## 5. Newer DDL conveniences :material-tag: **23ai+**

```sql
CREATE TABLE IF NOT EXISTS delivery_slots (slot_id NUMBER PRIMARY KEY);
DROP TABLE IF EXISTS delivery_slots;

-- A domain: a reusable column definition with its rule
CREATE DOMAIN email_d AS VARCHAR2(255)
    CONSTRAINT email_d_ck CHECK (REGEXP_LIKE(email_d, '^[^@]+@[^@]+\.[^@]+$'));

CREATE TABLE newsletter_subscribers (
    subscriber_id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email         email_d NOT NULL,
    is_confirmed  BOOLEAN DEFAULT FALSE NOT NULL
);

-- Annotations: metadata for tools and people
ALTER TABLE newsletter_subscribers MODIFY (email ANNOTATIONS (Classification 'PII'));
```

`IF [NOT] EXISTS` makes deployment scripts re-runnable. On 19c the same effect
needs a PL/SQL block that catches `ORA-00955` / `ORA-00942`.

## 6. Documenting and inspecting

```sql
COMMENT ON TABLE orders IS 'One row per customer order.';
COMMENT ON COLUMN orders.status IS 'PLACED -> PACKED -> SHIPPED -> DELIVERED, or CANCELLED.';

DESCRIBE orders
SELECT DBMS_METADATA.GET_DDL('TABLE', 'ORDERS') FROM dual;   -- full DDL
```

## 7. DCL in one page: GRANT and REVOKE

A new user can do nothing until privileges are granted.

```sql
-- System privilege: the right to perform an action
GRANT CREATE SESSION TO app_user;

-- Object privileges: rights on one object
GRANT SELECT, INSERT, UPDATE ON freshmart.orders TO app_user;
GRANT EXECUTE ON freshmart.order_pkg TO app_user;

REVOKE UPDATE ON freshmart.orders FROM app_user;

-- 23ai+: every current and future table in a schema
GRANT SELECT ANY TABLE ON SCHEMA freshmart TO reporting_user;
```

Group privileges into **roles** and grant the role. Full treatment in
[3.5 Security](../security/01-security.md).

## 8. Production recommendations

- Keep all DDL in version-controlled migration scripts ([4.9](../database-devops/01-devops.md)); never type it into production.
- Name every constraint.
- Applications connect as a user that **cannot** run DDL. The schema owner is used only by the deployment pipeline.
- Test the lock impact of each `ALTER` on a production-sized copy.

## 9. Common mistakes

- Running DDL in the middle of a transaction and committing half-done work by accident.
- Using `VARCHAR2(4000)` and `NUMBER` without precision "to be safe".
- Expecting CTAS to copy keys and indexes.
- `TRUNCATE` on a parent table: fails with `ORA-02266` while enabled foreign keys reference it (12c+ offers `TRUNCATE ... CASCADE` when the keys are `ON DELETE CASCADE`).
- Forgetting that a `DATE` has a time part.

## 10. Check yourself

??? question "Interview questions"
    1. **(Beginner)** DELETE versus TRUNCATE versus DROP? *See the table in section 4.*
    2. **(Beginner)** Can DDL be rolled back in Oracle? *No; it commits implicitly.*
    3. **(Intermediate)** Identity column versus sequence? *An identity column is a system-managed sequence bound to one column. A standalone sequence can be shared across tables and used before insert.*
    4. **(Senior)** How do you add a `NOT NULL` column with a default to a billion-row table without downtime? *Since 12c the default is stored as metadata, so `ADD (c NUMBER DEFAULT 0 NOT NULL)` is a dictionary-only change. Validate the lock duration and any dependent code first.*
    5. **(Architect)** What rules do you set for DDL in a 24x7 system? *Backward-compatible (expand, migrate, contract) changes only, online operations, edition-based redefinition or equivalent for PL/SQL, and pipeline-only execution.*

??? example "Exercises"
    1. Create `wishlist_items` with a composite primary key and two foreign keys.
       ```sql
       CREATE TABLE wishlist_items (
           customer_id NUMBER(10) NOT NULL,
           product_id  NUMBER(10) NOT NULL,
           added_at    TIMESTAMP DEFAULT SYSTIMESTAMP NOT NULL,
           CONSTRAINT pk_wishlist_items PRIMARY KEY (customer_id, product_id),
           CONSTRAINT fk_wishlist_customer FOREIGN KEY (customer_id) REFERENCES customers (customer_id),
           CONSTRAINT fk_wishlist_product  FOREIGN KEY (product_id)  REFERENCES products (product_id)
       );
       ```
    2. Add a `note VARCHAR2(100)` column, then drop the table.
    3. Find all constraints on `orders`: `SELECT constraint_name, constraint_type FROM user_constraints WHERE table_name = 'ORDERS';` *`P` primary, `R` foreign, `C` check (includes NOT NULL), `U` unique.*
